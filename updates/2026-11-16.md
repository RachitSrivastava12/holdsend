# 2026-11-16

## Done today

- Android emulator job in CI ([#72](https://github.com/zyakuhq/holdsend/pull/72), [decision 0016](../docs/decisions/0016-android-emulator-ci.md)). The Expo example is built as a release APK and installed on an Android 14 emulator. A note is written while the server is unreachable, the app's process is killed the way Android does it, the server comes back, and the background job is forced. The test checks that Android started the process for the job (no screen open), every attempt used one key, the note is published once, and a second run sends nothing.
- The job found a real bug on its first full run: Expo's Android template turns R8 on, and R8 removed the constructor of WorkManager's database, so the release build crashed at launch. The example now keeps it with a small config plugin, and the READMEs tell `expo-background-task` users to check a release build.
- Reviewed by a separate agent: the "no screen" check could pass on an empty dump, exactly once leaned on the server alone, the path filters were too narrow, and BACK could leave the app. All fixed before merge.

Expo's Android template turns R8 on for release builds, and R8 removed a constructor that WorkManager needs, so the app crashed at launch. The lesson: test the build people will ship, not the build that is easy to test. What shipped: a CI job that writes a note while the server is down, kills the app, forces the background job, and checks the note arrives exactly once from a process with no screen open, plus the fix for the crash. https://github.com/zyakuhq/holdsend
