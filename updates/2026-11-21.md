## LinkedIn post
Before every release I now ask a reviewer who did not write the code to read everything that changed since the last one. Today that was the work going into HoldSend 0.3.0. The review found nothing that loses a message or sends one twice. It did find a smaller thing: when a person approved an old message that the server had refused, the app could still label it "refused" while it was being sent again. Small, but a wrong label is how people lose trust in an offline app. The lesson for me is that every path back into the queue should go through one reset, not two copies of it. That is the fix: one shared reset and a test that fails on the old code. https://github.com/zyakuhq/holdsend
