# 2026-11-18

## Done today

- `main` CI is green again ([#79](https://github.com/zyakuhq/holdsend/pull/79), [decision 0017](../docs/decisions/0017-commit-email-exceptions.md)). The merge of #68 on 15 November went through GitHub's merge button, and that merge commit took a company address as author. Since then the "Secret and PII scan" job failed on every push to `main`. Pull requests still passed, because their range never includes that commit. The check is now `scripts/commit-email-check.mjs`, with tests, and it also runs in `npm run check`. On `main` it skips only the exact SHAs in `scripts/commit-email-exceptions.txt` (one today). Pull requests never use that list, a stale entry fails the check, and addresses are never printed. A separate agent reviewed the change and found four issues: a symlinked path could skip the check, the script itself had no tests, stale exceptions passed silently, and one claim in the decision was wrong. All four are fixed.

## LinkedIn post
Today's HoldSend work was about trust in CI, not features. One of our checks fails any commit that carries a company email address, and on the main branch it reads the whole history. Three days ago a merge made through GitHub's button picked up such an address. Every pull request still passed, but main turned red and stayed red, because the only real fix is rewriting published history. The lesson: a red build that nobody can fix is worse than no check, because it hides the next real failure. What shipped: the check is now a tested script that skips only exact listed commits on main, fails if that list ever points at the wrong commit, and still blocks every new commit with a company address. A separate reviewer found four gaps before merge; all fixed. https://github.com/zyakuhq/holdsend
