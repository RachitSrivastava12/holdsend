## LinkedIn post
Today a pull request from someone outside the team found a real bug in HoldSend. When a device lost its connection halfway through sending, our web helper told the browser the background sync was finished, so the browser stopped retrying while notes still waited on the device. Nothing was lost, but notes went later than they should. The lesson for me: "done" has to mean nothing is left to send, not just that the loop stopped. Before trusting the fix, I ran the contributor's tests against our current code and two failed, which proved the bug. Then a separate reviewer read the change. It is safe, and we found a smaller version that uses a third of the code size budget. Next step is landing it with credit. https://github.com/zyakuhq/holdsend
